# Vibe Studio · 产品文档

> 目的：让 AI 与新成员在 5 分钟内理解 Vibe Studio 是什么、解决什么问题、有哪些功能、用户怎么用。
> 阅读对象：产品/运营/新加入的工程师。

---

## 1. 产品定位

**Vibe Studio 是一个本地优先的「产品管理工作台」**，面向独立开发者 / 小型产品团队，把"产品信息、需求/Bug、版本、文档"四件事聚合到同一个产品上下文中，让一个人也能像一支产品团队一样管理手头多个产品的演进。

它不是：
- ❌ 团队协作 SaaS（无账号体系、无云端同步）
- ❌ 通用看板（Jira / Trello 的替代）
- ❌ 文档协作工具（Notion / Confluence 的替代）

它是：
- ✅ **本地工作台**：数据落在本机 SQLite，无云依赖、无注册
- ✅ **产品上下文聚合器**：把"产品卡片 + 任务 + 版本 + 文档 + Git 提交"装进同一个工作区
- ✅ **轻量级**：单页面应用，启动即用，关闭即走

---

## 2. 目标用户与场景

| 用户 | 场景 |
|---|---|
| 独立开发者 | 手头同时维护 2~5 个 side project，需要快速记录每个产品的进度、待办、版本号 |
| 小团队 Lead | 给团队建立一个"产品索引页"，每个产品关联一份 README 与当前版本 |
| 自由职业者 | 客户项目多，需要按"产品"维度组织任务与文档 |
| 产品经理 | 用 Markdown 记录产品需求，用任务看板跟进 Bug/需求 |

**核心心流**：新建产品 → 维护任务/版本 → 写文档 → 每天/每周回到工作台看 Git 提交与任务完成率。

---

## 3. 核心概念

```
产品 (Product)
├── 基本信息：名称、图标、描述、状态、用户数、应用 URL
└── 高级设置（默认折叠）：本地仓库路径、对外公开、自定义作品页路径
├── 任务 (WorkItem)：需求 / Bug，按状态分列
├── 版本 (Version)：计划中 / 已发布
├── 文档 (MarkdownDocument)：.md / .markdown 文件
└── Git 提交：通过本地仓库路径读取
```

四个 Tab：**概览 / 任务 / 版本 / 文档**，加上独立的**设置** Tab。

## 4. 功能清单

### 4.1 产品总览 `/products`

- 左侧"工作台 + 常用产品"导航（自动按 `archivedAt === null` 过滤）
- 活跃产品卡片网格，每张卡片显示：
  - 图标 + 名称 + 状态徽章
  - 任务完成率（按任务板自动推导）、未完成需求数、未完成 Bug 数、用户数、当前版本
  - **最新一条 Git 提交**（自动轮询 60s）
- 顶部"新建产品"按钮（弹窗表单）
- 底部"已归档"折叠区，可一键**恢复**

### 4.2 产品详情 `/products/:id/:tab`

进入产品后，默认进入 **概览** Tab。

#### 4.2.1 概览（overview）
- 状态徽章 + 标题 + 描述
- 任务完成率进度条（无任务时显示占位符）
- 4 个度量卡：未完成需求 / 未完成 Bug / 用户数 / 当前版本
- 详情列表：最近更新时间、Git 仓库路径
- Git 提交历史（最近 5 条，每 60 秒刷新）

#### 4.2.2 任务（tasks）—— 看板
- **三列看板**：待处理 / 进行中 / 已完成
- 卡片可拖拽跨列；支持同列内回拖（不写入）
- 筛选：`全部` / `需求` / `Bug`
- 顶部"新建任务"按钮
- **新建/编辑任务表单**字段：
  - 标题（必填）
  - 类型：需求 / Bug
  - 优先级：低 / 中 / 高 / 紧急
  - 截止日期：YYYY-MM-DD（本地时区）
  - 所属列（状态）

#### 4.2.3 版本（versions）
- 版本列表，按 `createdAt` 倒序
- 每行显示：版本号、状态（计划中 / 已发布）、发布备注、发布时间
- **当前版本**自动标记：状态为 `released` 且 `number === product.currentVersion`
- 新建/编辑版本：
  - 版本号（必填，产品内唯一）
  - 状态：计划中 / 已发布
  - 已发布时：发布日期（默认今天，ISO Z 时间）
  - 备注

#### 4.2.4 文档（documents）
- 左侧：文档列表（默认选中最近更新的）
- 右侧：Markdown 预览（带 XSS 过滤）
- **上传**：拖拽或选择 `.md` / `.markdown` 文件
  - 文件 ≤ 512 KiB
  - 文件名校验：trim 非空、≤ 180 字符、无控制字符、必须 `.md`/`.markdown` 后缀
  - 同名时弹出冲突 Modal：覆盖 / 另存为 / 取消
- **复制**：自动生成 `-副本`、`-副本-2` 等候选名
- **编辑**：直接改 Markdown 文本，保存
- **删除**：单条删除
- 预览安全策略：
  - 使用 `rehype-sanitize` 清洗
  - 自定义 `img` 标签直接被阻止（不渲染图片）
  - 自定义 `a` 标签只允许 `#锚点` / `http(s)://` / `mailto:`，其余外链被剔除

#### 4.2.5 设置（settings）
- 编辑全部产品字段（与新建表单同构）
- **多窗口冲突保护**：若其他窗口更新了同一产品，保存时弹出提示，提供"加载外部版本"按钮，原草稿保留
- **归档产品**：状态置为 `archived`，任务/版本/文档一并软删（在归档区可见，可恢复）
- 顶部"访问应用"外链（仅 HTTPS 才显示）

### 4.3 全局能力

- **a11y**：
  - 所有 Modal 有焦点陷阱、ESC 关闭、Tab 循环
  - 表单错误用 `aria-invalid` + `aria-describedby` 关联，错误信息 `role="alert"`
- **多窗口/多 Tab 安全**：
  - 所有 mutation 走乐观锁（`expectedUpdatedAt`）
  - 冲突时保留用户草稿，让用户决定覆盖还是回滚
- **Git 自动刷新**：进入产品页后每 60 秒拉一次最新提交
- **Markdown 安全预览**：`rehype-sanitize` + 自定义渲染器

## 5. 用户旅程

### 5.1 首次使用

```
1. npm run dev → 打开 http://localhost:6000
2. 自动跳到 /products，看到 3 个示例产品（Flora / ResumeGenius / Text War）
3. 点击任意产品进入概览，看 Git 提交列表（首次会显示提示，因为示例产品未配置真实仓库）
4. 进入"任务"Tab → 拖动卡片体验看板
5. 进入"文档"Tab → 上传一个 README.md 体验 Markdown 预览
```

### 5.2 新建产品

```
1. 工作台 → 右上角"新建产品"
2. 填写：名称、图标 emoji、描述、状态、用户数、应用 URL；
   本机 Git 仓库绝对路径、对外公开、作品页路径在「高级设置」中（默认折叠）
3. 提交 → 自动跳到 /products/:id
4. 在设置中可继续编辑；在任务/版本/文档 Tab 添加子资源
```

### 5.3 归档与恢复

```
1. 进入产品 → 设置 Tab → 点击"归档产品"
2. 状态变为"已归档"，任务/版本/文档被软删（在数据库中 is_deleted=1）
3. 回到工作台 → 展开"已归档"区 → 点击"恢复"
4. 产品及子资源全部恢复
```

### 5.4 多窗口协作（单机多 Tab）

```
1. 在 Tab A 编辑某个产品 → 不要保存
2. 在 Tab B 改了同一产品的字段并保存
3. 回到 Tab A 点击保存 → 弹出"产品已在其他窗口更新"
4. 选择"加载外部版本"放弃本地草稿，或保留草稿手动合并
```

## 7. 边界与限制

- **数据全部本地**：删除 `data/vibe-studio.sqlite` 等于清空数据；不同机器之间不同步。
- **单用户**：没有账号、没有权限区分；任何人都能修改任何产品。
- **Git 只读**：Vibe Studio 只读取提交，不会修改或推送。
- **图片不渲染**：Markdown 预览为了安全策略不展示图片，需要看图请下载或在 IDE 中打开。
- **大文档**：Markdown 单文件 ≤ 512 KiB；超过会被前端拒收。生产规模请用服务端对象存储。
- **端口固定 6000**：`strictPort` 开启，被占用就启动失败。
- **没有云备份**：SQLite 文件被 `.gitignore` 排除；用户需自行备份。

## 8. 与"老版本"的区别（迁移说明）

老版本 Vibe Studio 曾使用 `localStorage` + IndexedDB + Web Locks 做浏览器侧持久化。**当前版本已切换到 SQLite（服务端 Vite 中间件）**：

- 数据从浏览器 `localStorage` 迁移到 `data/vibe-studio.sqlite` 的工作**不自动进行**
- 老数据保留在浏览器存储中；用户清理站点数据会丢失
- 旧仓储（`src/data/studioRepository.ts`）保留供测试，新功能请直接走 SQLite API

## 10. FAQ（用户视角）

**Q: 数据存在哪里？**
A: `<项目根>/data/vibe-studio.sqlite`。删了等于全清。

**Q: 能在两台电脑之间共享数据吗？**
A: 当前不支持云同步。可以手动复制 SQLite 文件，或后续用 JSON 导入/导出。

**Q: Markdown 里能插图片吗？**
A: 不能，预览会过滤掉图片节点以保安全。Markdown 文本仍然完整保存。

**Q: 为什么拖动卡片没反应？**
A: 检查浏览器是否禁用 JS 或控制台是否有错误。拖拽使用 `@dnd-kit`，依赖 pointer 事件。

**Q: Git 提交列表空着？**
A: 在"设置"里检查 `repositoryPath` 是否为**绝对路径**、是否是合法的 Git 工作区。Git 失败只显示提示，不影响其他数据。

**Q: 我清空了浏览器存储，数据会丢吗？**
A: 当前版本的数据存在 SQLite，浏览器存储清理不影响。如果之前用的是老版本（localStorage），那才会丢。
