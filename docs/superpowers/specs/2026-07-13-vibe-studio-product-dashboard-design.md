# Vibe Studio 产品管理看板设计

## 1. 目标与首期范围

为个人 Vibe 开发者提供统一的产品管理工作台，集中记录多个项目的需求、Bug、版本、Markdown 文档与人工维护的产品指标，解决信息分散的问题。

首期交付范围仅包含产品域：

- 产品卡片总览与新建产品。
- 产品详情：概览、任务、版本、文档、设置。
- 任务看板，仅管理需求与 Bug。
- Markdown 文件上传及预览。
- 手动维护版本号和用户量。

数据与运营只在导航中预留为“即将推出”，不实现页面或数据能力。AI 助手、设计、数据看板、实验室、资源库、协作、Git 同步和自动发布均不在首期范围。

## 2. 目标用户与使用方式

目标用户是同时维护 Web、App、H5 游戏、桌面端等多类项目的个人开发者。用户打开工作台先浏览全部产品卡片，再进入特定产品处理需求、Bug、版本和文档。

产品之间数据严格隔离；用户可在没有任务、版本或文档的情况下创建产品。

## 3. 信息架构

### 3.1 全局导航

- 左侧导航以“产品”为唯一可用业务入口。
- 左侧可列出常用产品，点击进入相应详情。
- “数据与运营”显示为禁用态并标注“即将推出”。
- 保留设置入口。

### 3.2 页面层级

```text
产品总览（卡片）
├── 新建产品
└── 产品详情
    ├── 概览
    ├── 任务
    ├── 版本
    ├── 文档
    └── 设置
```

产品总览使用卡片布局而非产品树作为默认主界面。点击卡片进入独立详情页；详情页提供面包屑返回产品总览。

## 4. 界面原型说明

视觉采用参考图的桌面端浅色工作台风格：低饱和浅灰背景、白色圆角内容卡片、紫蓝色作为主强调色，产品图标作为次级识别色。首期不复制参考图中不属于产品域的任何模块。

### 4.1 产品总览

页面顶部包含页面标题、搜索入口（可作为视觉预留）和“新建产品”主按钮。主体为响应式产品卡片网格。

每张产品卡片显示：

- 产品图标、名称和一句简介。
- 状态：开发中、Beta、已发布或已归档。
- 未完成需求数和未关闭 Bug 数。
- 用户量和当前版本。
- 最近更新时间。

卡片主点击区域打开产品详情，状态和数量只作信息展示。

### 4.2 产品详情框架

顶部显示“产品 / 产品名”面包屑、产品图标、名称、简介，以及可选的“访问应用”外链。右侧提供编辑产品入口。下方固定页签顺序为：概览、任务、版本、文档、设置。

### 4.3 概览

概览展示产品状态、描述和关键指标卡：手动完成度、未完成需求数、未关闭 Bug 数、用户量、当前版本、最近更新时间。

完成度由用户手动填写。这避免在任务未完整录入时，用任务数量计算出误导性的进度。

### 4.4 任务

任务页面为单一看板，列固定为“待处理”“进行中”“已完成”。

- 每项仅有两种类型：需求、Bug；以色彩标签区分。
- 卡片显示标题、类型、优先级和截止日期。
- 支持按全部、需求、Bug 筛选。
- 支持创建任务和在列之间拖拽；拖拽改变状态。
- 完成项保留在“已完成”列，用于历史追溯，默认不删除。
- 概览中的需求和 Bug 统计只计算未完成列。

### 4.5 版本

版本通过人工创建记录，字段为版本号、状态、发布日期和变更说明。版本状态为“计划中”或“已发布”。

一个产品可以有多条版本记录。当用户将某条记录设为已发布时，系统将其版本号同步为产品的当前版本。首期不接入 Git tag、应用商店或发布平台；未来可在保持该数据模型的前提下增加同步来源。

### 4.6 文档

文档页只接受 `.md` 和 `.markdown` 文件。页面采用左侧文档列表、右侧 Markdown 渲染预览：

- 列表展示名称、上传时间和更新时间。
- 上传同名文件时，用户选择覆盖现有文件或另存为新文档。
- 不提供在线编辑、文件夹、协作、其他文件格式或格式转换。
- 非法格式拒绝上传；渲染失败时保留原文件并展示可理解的错误提示，不影响已有文档。

### 4.7 设置

设置管理产品名称、图标、简介、类型、状态、访问链接、完成度、用户量以及用户量统计口径/数据来源备注。

提供归档产品的危险操作。归档产品默认从总览隐藏，可恢复；首期不提供永久删除入口。

## 5. 手动指标策略

### 5.1 版本号

首期版本号完全人工维护，通过新增版本记录录入。已发布的最新记录成为概览的当前版本。这样适配 Web、移动端、游戏和桌面端各自不同的发布流程，且不会依赖尚未统一的 Git 或商店账号。

### 5.2 用户量

首期用户量为人工输入的当前累计值，并要求用户填写统计口径或来源备注，例如 App Store、友盟、Google Analytics 或业务后台 SQL。总览和概览读取该当前值。

后续接入按产品配置的统计 SDK/API 后，可增加自动同步时间和数据源；人工值仍可作为兜底或校正值。

## 6. 核心交互与数据流

```text
新建产品 → 出现在产品总览 → 进入产品详情
                           ├→ 创建/拖动需求或 Bug → 更新概览统计
                           ├→ 发布版本             → 更新当前版本
                           ├→ 上传 Markdown        → 文档列表与预览
                           └→ 编辑设置             → 更新卡片与概览指标
```

所有任务、版本和文档均以产品为父级。概览是聚合展示，不应成为各模块的独立数据来源。

## 7. 错误处理与边界

- 产品名称为空或重复时阻止保存并明确提示。
- 任务标题、版本号和文档文件为必填信息；缺失时阻止提交。
- 不允许上传 Markdown 以外的文件。
- 覆盖文档、归档产品等会影响既有内容的动作需要二次确认。
- 无任务、无版本、无文档时分别提供空状态和对应创建入口。
- 对已归档产品，保留数据但从正常产品卡片中隐藏。

## 8. 验收与验证

1. 创建产品后，产品卡片立即在总览展示，并可打开对应详情。
2. 创建需求/Bug、切换筛选、拖动列后，任务状态和概览中的未完成统计一致。
3. 新增并发布版本后，概览及产品卡片显示该当前版本。
4. 设置中修改用户量、完成度或产品信息后，总览与详情同步更新。
5. 上传合法 Markdown 后能选择并预览；非 Markdown 被拒绝；同名上传会要求选择覆盖或另存。
6. 归档产品后不在默认总览出现，但可通过归档状态恢复。

## 9. 后续演进（不纳入首期）

- 数据与运营：按产品接入用户、活跃、收入和反馈数据源。
- Git、发布平台、应用商店的版本自动同步。
- AI 助手对任务、版本、文档和提交记录进行总结。
- 设计资源、实验项目、多人协作与权限管理。
